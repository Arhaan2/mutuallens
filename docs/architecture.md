# Architecture and release boundary

The Astro public site and React checker run on separate browser origins. Public content contains no graph data; future advertising belongs only there. No cross-origin message bridge exists. All current preview pages are noindexed and ad-free.

The checker module worker imports untrusted JSON, inert HTML and selectively read ZIP entries, then compares supplied relationships. It does not execute uploaded markup or load embedded resources. Results are paginated without truncating the dataset; exports include all selected-category records. Imports remain in memory unless the user explicitly saves a local IndexedDB snapshot. Identity/date metadata is optional for comparison and required only where meaningful history needs it.

The owner's [amendment](specification/Core_Product_Amendment.md) makes upload comparison primary. It calculates supplied-list differences immediately while distinguishing mathematical absence from independently verified current Instagram relationships. Known partial imports remain usable with prominent warnings and exported limitations. Automatic-source negatives retain strict evidence gates.

A server-side Apify adapter and a resumable D1 job engine now exist. Every advance request performs a bounded state-machine step; source cursors, Apify dataset offsets and durable result pagination are distinct. A checkpoint before Actor start prevents automatic duplicate starts after uncertain acknowledgments. D1 transactional reservations and a unique active-job constraint enforce one scan at a time within configured credit ceilings. Reads/retries/timeouts/cancellation are bounded. Fresh account/price checks fail closed. The maintenance Worker erases expired local graphs independently of provider deletion and retries minimal remote resource IDs with backoff. Lost start acknowledgments without a provider run ID still need operator reconciliation.

These paths have synthetic transport/real local SQLite coverage, not live Instagram or deployed D1 evidence. The existing preview uses the disabled normal Pages configuration, with no database/token binding. The alternate automatic configurations and maintenance Worker are prospective and are not provisioned or deployed. See [automatic-integration.md](automatic-integration.md). Missing owner setup is explicit; it is not proof the candidate is impossible.

Advertising activation separately requires actual publisher/site approval, IDs, appropriate consent configuration and policy/security review. No claim of automatic target-scale acceptance or commercial production completion follows from a successful importer deployment.
